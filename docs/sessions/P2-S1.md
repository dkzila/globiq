**Status:** ✅ Complete

## Goal

Implement the `KnowledgeUnit` model and lifecycle (§43): the canonical semantic record — the reusable "thing to know", stored once (§7) — with explicit country scope (§14), canonical-identity deduplication (§11), §23 content types, time validity, and a §36 lifecycle state machine that makes silent edits of published knowledge impossible. Representations (ContentItem/QnA/Question) intentionally do **not** land here — they arrive in P2-S2+ and will reference these units.

## What Was Delivered

### 1. Schema (Prisma → Supabase)

- `KnowledgeUnitType` — FACT, CONCEPT, TIMELINE, PERSON_PROFILE, PLACE_PROFILE, ORGANISATION_PROFILE, COMPARISON (§23 canonical knowledge types; QnA/Question/MockTest are separate entities, representation formats are ContentItem formats — P2-S2).
- `KnowledgeStatus` — DRAFT → IN_REVIEW → VERIFIED → OUTDATED → ARCHIVED (public visibility = VERIFIED only; ARCHIVED is a read-only end-of-life like taxonomy RETIRED).
- `KnowledgeDifficulty` — BASIC, INTERMEDIATE, ADVANCED (the unit's inherent level; per-exam `required_depth` is ExamMapping, P3 — a different dimension).
- `KnowledgeUnit` — immutable URL-stable `slug`; `canonicalName`/`canonicalSummary` (quick fact, §22)/`canonicalBody` (English-reference; language versions are P2-S2 representations); explicit `scope` + `countryId` (§14 — never inferred); `topicId` (canonical taxonomy node, §13); `validFrom`/`validUntil` (§6 validity); `notes`; `orderIndex`; `createdById` (SetNull — authorship survives deletion like audit actors).
- `@@unique([topicId, canonicalName])` — §11 dedup by canonical identity: one canonical name per topic, globally unique slug.
- Indexes on status, (scope, countryId), (topicId, status), type.

### 2. Lifecycle State Machine (§36)

```
DRAFT ─submit_review→ IN_REVIEW ─verify→ VERIFIED ─flag_outdated→ OUTDATED
  │                       │                    │                     │
  └───────────────────────┴──────archive───────┴──────archive────────┘ → ARCHIVED (read-only)
                       send_back→DRAFT          reverify→VERIFIED
```

- **Editability per status**: full in DRAFT/IN_REVIEW/OUTDATED; **metadata-only in VERIFIED** (difficulty, validity window, notes, order — the body/name are locked); none in ARCHIVED.
- Corrections to a verified body MUST run: `flag_outdated` (reason **required** — §25/§36 correction provenance) → edit → `reverify`. The audit before/after diff is the interim revision history until ContentItem revisions land in P2-S2 — no silent edits ever.
- `KNOWLEDGE_TRANSITIONS` + `KNOWLEDGE_EDITABILITY` exported as the single state-machine source for service + UI.

## Key Decisions

1. **VERIFIED body lock instead of a revision table** — P2-S2 builds ContentItem revisions; until then the required `flag_outdated` → edit → `reverify` cycle + audit before/after diff guarantees no silent edit of published knowledge (§36) with zero extra infrastructure.
2. **Dedup = unique slug + unique canonicalName per topic (§11)** — canonical identity, never title similarity; cross-topic same names are legitimate.
3. **Scope-vs-topic containment invariant** — a unit under a country-scoped topic must share that country (mirrors taxonomy containment); global topics may hold global or any single country's units.
4. **A unit is never more visible than its topic** — public reads delegate visibility to taxonomy `getPublicTopic`; no duplicated scope logic.
5. **No snapshot cache for knowledge** (§29) — indexed queries now; the taxonomy cache pattern stays for the small read-everywhere tree. Documented trade-off.
6. **Public visibility = VERIFIED only** — OUTDATED units are correction-in-progress and stay private until re-verified.
7. `getTopicIdentity` exported from taxonomy as the cross-module topic lookup — module boundaries respected (knowledge never queries taxonomy tables directly).

## Handoff (for P2-S2: ContentItem and revisions)

- The lifecycle stays owned by the KnowledgeUnit; ContentItem statuses (draft→scheduled→published) layer on top in P2-S4's workflow.
- `KNOWLEDGE_TRANSITIONS`/`KNOWLEDGE_EDITABILITY` are the shared state-machine vocabulary — import them rather than re-deriving rules in the UI.
