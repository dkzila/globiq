## Key Decisions

1. **`content:publish` as its own permission** — §18's "cannot publish unless granted" becomes a role-level gate (ADMIN + COUNTRY_ADMIN); WRITER can never hold it. Affordances are server-filtered (`allowedTransitions`), so writers never even see publish/schedule/retire buttons — the server re-checks regardless (§20).
2. **SCHEDULED locks the working copy** — the review approval is a contract: what was reviewed is exactly what publishes. Edits require send_back → DRAFT → re-submit (§19).
3. **Lazy materialization instead of a scheduler** — due SCHEDULED items publish on the first read after their time (public or admin), atomically via a conditional-claim transaction; race-safe, audited as a system publish. Documented trade-off: without a background job, the publish moment is the first read, not the wall-clock instant.
4. **Tasks inherit the work object's scope** — countryId from the owning unit (GLOBAL units → platform tasks, ADMIN-only board — §38 parity with content); languageId from the item. Tasks are never country-set by hand.
5. **§19 wiring is transactional** — task open/resolve/cancel rides the content transition's transaction via `wireContentWorkflow`, so the board can never lag content state. Audits stay best-effort outside the tx (the documented P1-S5 trade-off).
6. **§19 separation of duties enforced at task level** — the auto-opened review task records the submitter; a WRITER cannot claim/start/resolve their own submission's review (self-approval blocked). Editors are never blocked.
7. **Language scope narrows management, not read** (§20) — a Hindi-scoped writer SEES the country board (context) but can only work language-compatible tasks and manage hi representations.
8. **Sources stay platform-level; writers get `source:manage`** per the P2-S3 handoff — writers register/verify evidence; citation link/unlink rides `content:manage` on the item (which writers now hold, scoped).
