### 2. Versioning Model (§36 — the session's core design)

- **Windows are day-granular and non-overlapping.** The CURRENT version is the one whose `[effectiveFrom, effectiveTo]` window contains now — `currentVersion` on every payload is the §11 engine's resolution point.
- **Creating a version closes the open predecessor at (newFrom − 1 day)** — the supersede step. Windows are IMMUTABLE afterwards: history is append-only; corrections are a new version, never an edit.
- **Pre-effective correction path**: a FUTURE-dated LATEST version may be removed (it never entered history); the predecessor it auto-closed is reopened deterministically (effectiveTo was exactly newFrom − 1 day). In-effect versions are never removable (`VERSION_ALREADY_EFFECTIVE`).
- Error vocabulary: `VERSION_WINDOW_INVALID` (400 — would corrupt the open window), `VERSION_OVERLAP` (409 — no open version, window clashes with a closed one), `VERSION_NOT_LATEST`/`VERSION_ALREADY_EFFECTIVE` (409 — removal guards).

## Key Decisions

1. **Exams are configuration, not content** — they do not ride the §19 review workflow. DRAFT → ACTIVE is provisioning by Country Admins (§18); lifecycle states exist for public visibility and end-of-life, with `retire` requiring an audited reason.
2. **No exam deletion, ever** — consistent with the platform-wide migration-safe philosophy (Topics RETIRED, KUs ARCHIVED, Tasks never deleted). A retired exam is history; its versions and (future) mappings remain queryable.
3. **Version windows are append-only (§36 taken literally)** — a window is immutable after create; the only correction path is removing a future-dated latest version (which never entered history) with deterministic predecessor reopen. This is the invariant P3-S2/S3 mappings rely on: `ExamMapping` rows pinned to a version can never have their window mutated underneath them.
4. **currentVersion is computed, never stored** — resolution is `windowContains(now)` over non-overlapping windows; the §11 engine consumes this field directly.
5. **slug globally unique; code unique per country** — exam URLs need country-prefix disambiguation in principle, but global slug uniqueness matches the platform's URL-stable identity pattern (topics, KUs) and keeps refs deterministic.
6. **COUNTRY_ADMIN has no global fallback on exams** — unlike knowledge units (which can be GLOBAL), exams are always country-owned, so the country-admin board is strictly their market; ADMIN operations may target COMING_SOON countries (launch prep) while the public surface enforces ACTIVE (§15).
7. **Public exam reads ship §16 canonical paths as data** — same pattern as P2-S5 knowledge pages: `/exams/{slug}/` for the India root market, `/hi/exams/…` for Hindi, built by `buildCanonicalUrl` from country + language + object identity. The real routes land in P3-S5/P4-S4.
8. **`exam:manage` is Country Admin + Admin only** — §18's Exam Specialist is a future fine-grained role; WRITERs get nothing exam-related today.
