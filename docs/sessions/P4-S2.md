### 2. `GET /api/home` — the §34 country homepage composition

- **Reader context** resolved server-side (§14/§35); unknown/INACTIVE → typed 404; **COMING_SOON resolves** (§15 — data scoping, not a wall).
- **GK categories** = the top-level §13 domains visible in the country, each with its localised label (requested → country default → canonical), description, §16 `/gk/{slug}/` path, subtree topic/unit counts (VERIFIED units only, GLOBAL + own-country scope), and first-level branch chips with counts (§33 cluster preview).
- **Major topics** = non-domain nodes ranked by subtree unit count (desc) then tree order then slug — deterministic §37; breadcrumb labels from the domain down.
- **Exams** = the country's ACTIVE exams (name asc), each with its CURRENT §36 version (windowContains) and its **§8 in-effect mapping count** on that version (`mappingInEffect` — the exact requirement-layer predicate). COMING_SOON markets get the quiet state with reason.
- **Popular knowledge** = up to 6 VERIFIED units in editorial order (orderIndex, canonicalName — deterministic until P8 analytics), each with the **§22 quick-fact resolution**: published FACT_CARD in the reader's language, else the canonical summary with `source: CANONICAL_SUMMARY, language: 'en'` (the UI labels the fallback — a homepage never pretends a translation exists); plus the topic label and the §8 exam count (distinct ACTIVE exams needing the unit today).
- **Current affairs** = the honest quiet state with a pointer to the Current Affairs category hub.
- **§35 language switcher** = only the country's configured languages, each with its §16 home URL.
- **Stats** = visible topics, VERIFIED units, ACTIVE exams.

## Key Decisions

1. **The homepage is a computed view** (§7): nothing persists; category/major/exam/unit sections are assembled per request from the canonical model with the same visibility rules as every public read (§14/§36). "Popular" is deterministic editorial order until P8 analytics can rank by real usage — honest, never fake.
2. **Quiet states are discriminated unions, not empty lists**: COMING_SOON exams (`reason: 'COUNTRY_COMING_SOON'`), the P6 current-affairs feed, and the §35 canonical-fallback summary all carry explicit markers the UI renders honestly — an empty ACTIVE-country list stays a real empty list (§36/§45).
3. **COMING_SOON markets browse** (§15): GB/FR homepages resolve and show the global content legitimately visible to them (global taxonomy + GLOBAL-scoped units) with a launch-state exam card — data scoping, never network blocking.
4. **`mappingInEffect` exported from exam-mapping**: the §8 liveness predicate is now shared public interface — the seo compositions aggregate with exactly the requirement layer's semantics (CURRENT version + in-effect mapping), never a re-implementation.
5. **§16 mirrored after the hash**: the sandbox constraint (browser path stays `/`) is satisfied by reproducing the canonical URL grammar after `#` — same segments, same default-omission rules, driven by the live country/language config; the server's `buildCanonicalUrl` remains the single source of path truth and every §16 path ships as data on cards and results. Addressable `?page=N` pagination derives from the hash — no duplicated state, back-button works.
6. **The unit view reuses P2-S5's `KnowledgePageView` unchanged** — the discovery surface wires the existing §22 reader into the navigable product; the homepage's unit cards would otherwise be dead ends, and no new backend surface was needed (session scope respected: exam click-through stays a path display until P4-S3's exam/syllabus SEO pages).
7. **The foundation console stays one click away** — every prior session's verification surface (and the §17 regression chips) remains reachable via the Console link and the `#account` anchor; the product surface replaces the foundation page as the default, per the P4-S1 handoff note.
