# Session Report — P4-S1: Search Abstraction and Indexing Pipeline

## Goal

Implement the §17 search product as a **first-class, vendor-neutral capability** (§43 P4-S1): an indexing pipeline that projects the platform's public canonical objects into a searchable document store, and a query engine implementing every §17 clause — exact/prefix matching, typo tolerance, language-aware tokenisation, editorial aliases, country-aware filtering, exam-aware boosting, freshness boosting, canonical-object deduplication and match explanations — behind an abstraction that never couples the domain model to a search vendor (§29).

## What Was Delivered

### 1. The vendor-neutral index format (`prisma/schema.prisma` — `SearchDocument` + `SearchObjectType`)

One row per **public object × indexed language variant** (`@@unique([objectType, ref, languageCode])`): `KNOWLEDGE_UNIT | EXAM | TOPIC`. The table is the platform's OWN index format (§29) — moving to a managed engine later re-points the adapter, never the domain model. Fields: denormalised `countryIso` (null = GLOBAL, §14), localised `title`/`summary`/`bodyText`, language-neutral `neutralText` (canonical name + §13 aliases + slug tokens), `aliases` JSON, `examRefs` JSON (exams whose CURRENT §36 version carries an in-effect §8 mapping), `freshnessAt`, and two **index-time tokenised** tsvector columns (`tsvLang` with the language's FTS config, `tsvNeutral` with `simple`) written via raw SQL upserts.

### 2. The engine — the only vendor-aware file (`src/modules/search/engine.ts`)

`SEARCH_ENGINE_ID = 'postgres-fts-v1'` surfaced on every response (§29). Language-aware tokenisation resolves live against `pg_ts_config` (cached): **en→english, hi→hindi** (the Supabase Postgres build ships the Snowball Hindi stemmer — verified live: `to_tsvector('hindi', 'चंद्रयान …')` stems correctly); unlisted languages fall back to `simple` (tokenisation without stemming). `ensureSearchEngineReady()` is idempotent and cached per process: creates `pg_trgm` + the four GIN indexes — self-healing because `prisma db push` may drop them. `querySearchCandidates()` is the retrieval port: reader-country scope, type/§8-exam filters, and the two §35 match lanes — reader-language documents match on localised text OR neutral text; other-language documents match on neutral text ONLY (a search never surfaces a translation that doesn't exist). Prisma's tsvector/tsquery deserialisation limits are handled with `::text`/`::regconfig` casts.

### 3. The indexing pipeline (`src/modules/search/indexing-service.ts`)

- **Unit documents** (§7): one document per language with ≥1 PUBLISHED representation (§35); title = canonicalName (canonical identity — representation titles live in bodyText); summary = that language's FACT_CARD body else canonicalSummary; `examRefs` from CURRENT in-effect §8 mappings of ACTIVE exams. A VERIFIED unit **without** any published representation still gets ONE canonical-reference `en` document (§6 — the unit is itself a searched object; the §22 page renders the canonical record). §14 effective scope: GLOBAL unit under GLOBAL topic → visible everywhere; otherwise the owning market, which must be ACTIVE.
- **Topic documents**: one per language carrying a §13 label (canonical `en` fallback when label-less) — the future `/gk/{topic}/` hubs.
- **Exam documents**: ACTIVE exams of ACTIVE markets, indexed once in the market's default language (names are canonical §14 metadata; other languages find exams through neutral text).
- **Hooks** (freshness by construction — one-way dependency, no import cycles): `onUnitChanged` (knowledge create/update/transition + content publish/retire/materialize), `onTopicChanged` (topic create/update/retire/labels/aliases — ripples to all units under the topic), `onExamChanged` (exam update/transition/version create+remove — ripples to mapped units), `onMappingsChanged` (mapping CRUD). Hook failures log and never break the parent mutation; the full rebuild heals any gap.
- **`reindexAll()`**: idempotent full rebuild — projects every public object, then removes documents of objects that left the public surface AND stale language variants of live objects (§36: a full reindex leaves no stale rows).
- **`getIndexStats()`**: counts by type/language, engine id, live FTS config map, lastIndexedAt (§38 admin console).

### 4. The query service (`src/modules/search/query-service.ts` — every §17 clause)

Portable tier scoring (alternatives, strongest tier wins) + additive boosts:
- **§17.1** EXACT_TITLE 1000 / EXACT_ALIAS 950 / TITLE_PREFIX 800 / ALIAS_PREFIX 760 / TITLE_CONTAINS 700 (exact + prefix on titles and editorial aliases)
- **§17.3** FTS 500 + ts_rank·400 (language-aware full text), NEUTRAL_FTS 450 (canonical/alias in the reader-language doc)
- **§17.2** FUZZY_TITLE 300 + similarity·200 / FUZZY_BODY 250 + word_similarity·100 (pg_trgm typo tolerance; gated to queries ≥4 chars — a 2-char trigram match like "fr"~"from" is noise; title threshold 0.25 tuned so "chandrayan"→Chandrayaan-3 lands inside)
- **§35 canonical-fallback lane** (capped below reader-language): exact 600 / prefix 550 / FTS 400 / fuzzy 200 — the object matched through canonical identity, presented with an honest "no published content in this language yet" reason
- **§17.6** +120 exam boost, with "In the current {exam} syllabus" explanations per reader-country exam (§14 — never another market's exams)
- **§17.7** ≤+30 freshness (CurrentEvent joins here in P6)
- **§17.8** dedup by (objectType, ref): the reader-language document always beats the same object's other-language document
- **§37** deterministic ordering: score → type rank (units, exams, topics) → title → ref; page/pageSize pagination
- **§16** paths built ONLY via `buildCanonicalUrl` in the reader's language (`/gk/{topic}/{slug}/`, `/gk/{topic}/`, `/exams/{slug}/`, `/hi/…`)
- `GET /api/search` (public, rate-limited 60/min) returns query echo + results + pagination + index health (engine id, documents, lastIndexedAt, tookMs).

## Key Decisions

1. **The engine is the only vendor-aware file** (§17/§29). Document builders, tier scoring, dedup, explanations and §16 path building are vendor-neutral; swapping PostgreSQL FTS for a managed engine re-implements candidate retrieval only.
2. **Index-time tokenisation** (tsvLang/tsvNeutral computed in the upsert), not query-time — §17's "language-aware tokenisation" lives in the pipeline, and queries only tokenize the query itself.
3. **One document per object × language-with-published-surface (§35), plus a canonical `en` document for representation-less VERIFIED units (§6)** — the unit is a searched object; its fallback presentation matches the §22 page's canonical-summary behaviour and is always labelled honestly.
4. **Two match lanes**: reader-language documents score through the full tier ladder; other-language documents only through canonical identity, capped lower — a search never surfaces or ranks a translation that doesn't exist.
5. **`examRefs` stored globally, scoped at query time** — the document records which exams (any country) require the unit today; the reader's country's exams drive boosting/explanations (§14: a GB exam's requirement never leaks into an IN reader's result).
6. **Hooks are one-way and never fatal** — feature modules call the search module after visibility-affecting mutations; the search module imports none of them back (reads canonical data via Prisma directly, mirroring §36 window semantics locally). A failed hook logs; the audited admin rebuild heals.
7. **Typo tolerance is gated to ≥4-character queries** — pg_trgm on 2-char strings produces substring noise ("fr" ~ "from"), not typo tolerance; short queries are served by exact/prefix/contains/FTS tiers.
8. **Full rebuild = upsert-then-prune** — documents of departed objects and stale language variants are deleted after re-projection, so `reindexAll` is truly idempotent (§36: nothing stale survives).
