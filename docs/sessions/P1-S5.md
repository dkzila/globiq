## What Was Delivered

### 1. Schema (Prisma → Supabase)

- `AuditLog` — append-only trail: `actorId` (FK User, `onDelete: SetNull` — the trail survives account deletion), denormalised `actorEmail` + `actorRole` (accountability after deletion), namespaced `action` (e.g. `taxonomy.topic.update`), `objectType`/`objectId`/`objectLabel`, `before`/`after` JSON (redacted at write), `metadata` JSON (request context, denial reasons), `ip`, `userAgent`, `createdAt`. Indexes on createdAt, (actorId, createdAt), (objectType, objectId), (action, createdAt). Rows are never updated or deleted.

### 2. Shared Permission Layer (`src/lib/permissions.ts`)

- Placed in `src/lib` as a **dependency leaf** (the permission core of the Identity & Access module) so country-locale and taxonomy services can enforce without an identity-access ⇄ country-locale import cycle.
- `Permission` vocabulary: `taxonomy:manage`, `country-config:manage`, `language:manage`, `audit:read`, `sessions:manage-own`.
- `can(actor, permission, target?)` — category-level gate; with `target.countryId` it makes object-level decisions: **COUNTRY_ADMIN may only act on objects of their own country; global objects (countryId null) are ADMIN-only** (§13/§20/§38). ADMIN: everything; WRITER/READER: own sessions only in P1 (editorial scopes land P2-S4).
- `assertCan` (service-boundary enforcement), `effectivePermissions` (surfaced via /api/auth/me for UI affordances — never for enforcement), `PermissionDeniedError` (403), `PERMISSION_LABELS`.

### 3. Audit Module (`src/modules/audit/`)

- `service.ts` — `recordAudit` (best-effort, never throws: a failed audit insert must not break a completed operation; events recorded post-commit — documented trade-off) with automatic **redaction** (any key matching password/token/secret/credential/authorization → `[redacted]`, depth + string-length caps); `listAuditLogs` (enforces `audit:read` at the service boundary; filters: action, actor-email substring, objectType, objectId, from/to; deterministic ordering createdAt desc + id desc; filter-coherent summary {total, last24h, topActions} + whole-trail facets for UI dropdowns).
- `types.ts` — `AUDIT_ACTIONS` vocabulary (17 keys incl. `access.denied` route-gate denials, `taxonomy.topic.denied` object-level denials, `auth.login.failed`), `AUDIT_OBJECT_TYPES`, DTOs. `validation.ts` — zod query schema (page ≥1, pageSize 1–100).

### 4. Permission Enforcement Wiring (§37: service boundary + defense in depth)

- `src/lib/api/guard.ts` — `requirePermission(request, permission, target?)` replaces `requireRole` everywhere: authenticates → builds the shared `Actor` (role + resolved home country via `actorFromUser`) → `can()` check → **every denial is audited** (`access.denied` with method/path/permission/ip/userAgent) → 403. Returns `{ user, session, actor }` so routes no longer resolve actors themselves.
- **country-locale** — all 5 mutations (`createCountry`, `updateCountry`, `setCountryLanguages`, `createLanguage`, `updateLanguage`) now take `actor` + `meta` as first-class params, `assertCan` at the service boundary (route guard = defense in depth), and record before/after audits with changed fields.
- **taxonomy** — `TopicActor` retired in favour of the shared `Actor`; `canManageNode` delegates to shared `can(actor, 'taxonomy:manage', {countryId})`; object-level denials (GLOBAL node as COUNTRY_ADMIN, cross-country access, retired-node writes, root/global create attempts) record `taxonomy.topic.denied` with the reason while preserving the established API error codes (§37 stability); all 5 mutations record before/after audits (labels/aliases diffs included).
- **identity-access** — `actorFromUser` added; auth events audited: `user.register`, `auth.login`, `auth.login.failed` (anonymous actor, attempted email + reason in metadata — ADMIN-only visibility, the API response itself stays enumeration-safe), `auth.logout`, `auth.session.revoke`.

## Key Decisions

1. **Permission layer lives in `src/lib/permissions.ts`** (leaf), not inside a module import — avoids the identity-access ⇄ country-locale cycle while remaining the single source of authorization truth. Documented in the file header.
2. **Denials are audited, not just successes** — route-gate denials (`access.denied`) and object-level taxonomy denials (`taxonomy.topic.denied`) give admins the §20 "who tried to cross a border" signal.
3. **`recordAudit` is best-effort post-commit** — a failing audit insert never breaks a user operation; crash-window loss documented (revisit with a transactional outbox if required).
4. **API error codes unchanged** — taxonomy keeps `GLOBAL_NODES_ADMIN_ONLY`/`COUNTRY_MISMATCH` etc. (§37 stability); permission denials at the route gate use `FORBIDDEN` with the permission key in the message.
5. **Actor identity is denormalised** (email/role at action time) with `actorId → SetNull` — accountability must survive account deletion (§204 "Accountability").
6. **Login failures audited with the attempted email** — ADMIN-only trail; the public API response stays enumeration-safe (uniform INVALID_CREDENTIALS).
7. `GET /api/languages` gates on `taxonomy:manage` — preserves the P1-S4 COUNTRY_ADMIN label-editor read while keeping writes ADMIN-only.
