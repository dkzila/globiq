## What Was Delivered

### 1. Render Service (`src/modules/knowledge/render-service.ts` + `render-types.ts`)

- `getKnowledgePage(ref, {country, language})` — assembles the whole §22 page in one call:
  - **Canonical record** — slug/name/summary/body, type/difficulty/scope badges, validity window, topic breadcrumb from the public taxonomy path.
  - **Quick fact (layer 1)** — the FACT_CARD representation when published, else the canonical summary (the record is ALWAYS renderable — never a blank page).
  - **Deeper explanation (layer 2)** — published representations in the resolved language, ordered by the §22 flow (EXPLAINER → PROFILE → COMPARISON → TIMELINE → REVISION_NOTE → CURRENT_EVENT_UPDATE), each with revision info + §26 AI-provenance flag.
  - **Sources (layer 3)** — §24 evidence aggregated across the displayed representations (unique per source, VERIFIED-first ordering), each with verification state, claim, and `citedBy` back-references to the representing items.
  - **Related concepts (layer 4)** — sibling VERIFIED units under the same topic (country-visible, §14), each with its `availableLanguages` (the §35 "read it in…" signal) and its §16 canonical path.
  - **Exam coverage (layer 5)** — an explicit placeholder (`available: false`) with the P3 note — the layer EXISTS from day one; ExamMapping data is never fabricated before Phase 3.
- **§23 format-aware parsing, server-side** (client-agnostic, §37): TIMELINE "date — event" lines → `parsed.timeline[]`; COMPARISON "axis | left | right" → `parsed.comparison[]`; PROFILE "key: value" → `parsed.profile[]`. Lenient by design — the raw `body` always ships alongside; unparsed bodies render as prose.
- **§16 canonical paths** via the country-locale URL builder (`buildCanonicalUrl`): `/gk/{topic}/{unit}/` (IN/en), `/hi/gk/…` (IN/hi), `/{country}/gk/…` for other markets — generated from country + language + object identity, never from user input. Shipped as DATA (the real routes land in P4-S4).
- **§35 translation surface** — `translations[]` = country-configured languages that ACTUALLY carry a published representation (the hreflang-honest set), each with its canonical path.
- **§19 integration** — due SCHEDULED releases materialize before assembly (`materializeDueScheduledContent`, now exported from content-service); `scheduledCount` surfaces "goes live soon" items.
- **Language negotiation** — resolved via the country-locale context (only configured languages); a language with zero published representations still serves the page (canonical layers + related + a data-driven "not yet published" state) — §35 never fabricates availability.

## Key Decisions

1. **The page is an assembly, not a copy (§7)** — `getKnowledgePage` composes the existing public read paths (unit visibility P2-S1, live revisions P2-S2, provenance P2-S3, scheduled materialization P2-S4). It never bypasses their visibility chains and never stores rendered output — dedup stays canonical by construction.
2. **FACT_CARD is the quick-fact layer** — §22's "quick fact" maps to the FACT_CARD format; when absent the canonical summary renders instead, so a page is never blank while the record is VERIFIED.
3. **§23 parsing is server-side and lenient** — structured `parsed` payloads (timeline/comparison/profile) make the API genuinely client-agnostic (§37/§39); the raw body always ships, so lenient parsing can never lose information and unparsed bodies degrade to prose.
4. **§16 canonical paths ship as data now** — built by the existing `buildCanonicalUrl` from country + language + object identity. The SEO surface (real routes, hreflang tags, sitemaps) stays in P4-S4; P2-S5 provides the URL model every layer will link with.
5. **Translations expose only published reality (§35)** — `translations[]` comes from actual PUBLISHED representations in country-configured languages, mirroring the hreflang-honesty rule. A language without publications gets a data-driven "not yet published" reading state, not an error and never a fabricated page.
6. **Exam coverage is an explicit P3 placeholder (§22/§8)** — the layer renders today with `available: false`; ExamMapping (P3-S3) fills it with real exam/depth data. Never fabricated early.
7. **Reader = ACTIVE countries only** — COMING_SOON markets (GB, FR) have no public content yet (§15); they are not offered in the reader's country picker, and requests for them return clean 404s.
8. **Public-path error hardening (§37)** — unknown/inactive countries on ALL public knowledge reads (page + the pre-existing list/detail) now return clean 404s instead of 500s; LocaleError never leaks past the service boundary.
