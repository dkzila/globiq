## What Was Delivered

### 1. Schema (`prisma/schema.prisma`)

**`SyllabusNode`** — id, examVersionId (the §36 anchor), parentId (self-relation `SyllabusTree`; null = root; same-version only), **name** (the exam's own notification wording — §13: never taxonomy), **topicId** (optional canonical Topic link — the ONLY exam → taxonomy bridge), depth (denormalised parent.depth + 1), priority (§6 sibling ordering), notes. Indexes: `(examVersionId, parentId, priority)`, `(topicId)`. Relations wired on `ExamVersion.syllabusNodes` and `Topic.syllabusNodes`.

### 2. §36 Editability Model (the session's core design)

A tree is **`staged`** while it may still change: the exam is DRAFT (private provisioning — nothing publicly consumed) or the version is future-dated. It becomes **`frozen`** the moment a non-DRAFT exam's version window starts — the tree is §36 history and never mutates again (corrections create a new ExamVersion, exactly like the windows themselves) — and **`locked`** when the exam retires. Every write path funnels through `loadEditableTree` (scope check → version membership → editability), so the guard is impossible to bypass.

### 3. Module (`src/modules/exams-syllabus/syllabus-service.ts` + extensions)

- **Public read** `getPublicExamSyllabus` — the syllabus a reader sees today: the CURRENT version's tree by default (§11 step 2 resolution), or an explicitly requested version that has STARTED (§36 historical query; future/staged trees are never public). Topic labels resolved per §35 (requested language → country default → canonical name) and §16 syllabus-topic paths shipped as data (`buildCanonicalUrl`).
- **Admin read** `getAdminVersionTree` — any version incl. staged/future trees, with the editability verdict + reason so the UI renders affordances from server truth.
- **Node CRUD** — create (same-version parent, §13/§14 topic-link guard: GLOBAL or the exam's own country's topics only), update/move (ancestor-chain walk blocks subtree cycles; subtree depths shift by the move delta), delete (leaf-only — `NODE_HAS_CHILDREN`).
- **Bulk outline import** `importSyllabusOutline` — the primary staging path: indented plain text (2 spaces or 1 tab per level, `#` comments, blank lines skipped; one-level-at-a-time deepening) parsed server-side and replacing the entire staged tree in one transaction; an empty outline clears staging. 2000-node cap.
- **`removeExamVersion` guard (P3-S1 handoff closed)** — a version carrying SyllabusNodes is `VERSION_REFERENCED` (409): a referenced version is history; the pre-effective correction path only exists for unreferenced versions.
- Error vocabulary: `VERSION_FROZEN`, `VERSION_NOT_STARTED`, `NODE_NOT_FOUND`, `PARENT_INVALID`, `INVALID_MOVE`, `NODE_HAS_CHILDREN`, `TOPIC_NOT_FOUND`, `TOPIC_COUNTRY_MISMATCH`, `OUTLINE_INVALID`, `VERSION_REFERENCED` (all typed → HTTP via the module's single error mapper).
- `ExamVersionRef` payloads now carry `nodeCount` (admin version timeline + public detail).

## Key Decisions

1. **Trees are frozen the moment their version enters history** (non-DRAFT exam + started window). Staging lives on future-dated versions and DRAFT exams (private provisioning — nothing publicly consumed). This is the §36 rule applied one level deeper than P3-S1: windows are immutable; so are the trees pinned to them.
2. **`name` (exam wording) + optional `topicId` (canonical link)** — §6's field row is a summary; the exam's own syllabus labels ("Prelims — Paper I") never enter the taxonomy, while the topic link is the single §13 bridge to canonical knowledge.
3. **Topic links are country-guarded (§13/§14)** — a node may link GLOBAL topics or its own exam's country-scoped topics; another country's taxonomy extension is a 400 `TOPIC_COUNTRY_MISMATCH`, enforced server-side.
4. **No hard delete of frozen trees, ever** — deletes (leaf-only) and imports exist only in staging; a frozen tree's only correction path is a new ExamVersion, mirroring the append-only windows.
5. **`removeExamVersion` now refuses referenced versions** — closing the P3-S1 TODO; the deterministic predecessor-reopen still works after the tree is cleared.
6. **Public historical syllabus reads exist** (`?version=` on started versions) — §36 "old mappings remain historically queryable" is now demonstrable end-to-end; future/staged versions are never public.
7. **Outline import is the primary editorial path** — teams paste the official notification's structure once instead of clicking a tree into existence; the parser is lenient on formatting but strict on structure (indent jumps, mixed units, depth jumps are explicit 400s with line numbers).
8. **`exam:manage` remains the gate** — §18's Exam Specialist is still a future fine-grained role; syllabus operations ride the same Country Admin/Admin permission as exams, with the same audited object-level denials.
