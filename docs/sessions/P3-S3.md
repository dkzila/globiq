**`ExamMapping`** — the §6 row exactly: `knowledgeUnitId` + `examVersionId` + `syllabusNodeId` anchor triple, `relevance`, `priority`, `requiredDepth`, `questionLikelihood`, `expectedScope`, `sourceBasis`, `effectiveFrom/effectiveTo` (§8 effective_period, day-granular inclusive; null = whole version window), `notes`. `@@unique([knowledgeUnitId, syllabusNodeId])` — one mapping per unit per node (the node implies the version). ### 2. §36 mapping editability — the session's core design decision

The P3-S2 handoff guessed mappings would freeze with the version like the tree. **That reading contradicts §12**: "a current-affairs item flows directly into a followed exam's combined queue the moment it's mapped" is only possible if mappings can be ADDED to an in-effect version (events occur mid-window). The implemented model (`mappingEditability`, documented in the schema and service headers):

- **`staged`** — DRAFT exam or future-dated version: tree + mappings editable.
- **`live`** — the CURRENT version in effect on a non-DRAFT exam: **mappings editable** (audited), tree stays frozen (P3-S2 rule unchanged).
- **`frozen`** — started but superseded: §36 history, read-only ("old mappings remain historically queryable").
- **`locked`** — RETIRED exam.

## Key Decisions

1. **Mappings stay writable on the CURRENT version** (`live`), unlike the tree — §12's current-affairs flow demands it; only superseded versions freeze mappings as §36 history. The deviation from the P3-S2 handoff's guess is documented in the schema and service headers with the §12 rationale.
2. **A separate `exam-mapping` module** (per the §28 registry): mapping-service imports exams-syllabus's public helpers; the reverse never happens.
3. **`relevance` = nature of the unit→node fit** (DIRECT/PARTIAL/CONTEXTUAL), kept distinct from `priority` (CORE/SUPPORTING/LOW) — two §8 axes, never collapsed into one score (§8: "avoid simplistic universal scoring").
4. **Anchors are immutable** — re-anchoring a mapping means remove + re-create, both audited; `examVersionId` is derived from the node server-side, never trusted from the client.
5. **No silent mapping loss anywhere**: node deletion, outline import and version removal all refuse while mappings exist — every mapping removal is an explicit, audited editorial act.
6. **Console may map non-VERIFIED units** (editors stage mappings while knowledge is in review); the public coverage read filters VERIFIED + country-visible + currently-in-effect, and surfaces the unit status so editors see what is hidden.
7. **Historical coverage reads keep expired mappings** (§36 "old mappings remain historically queryable"); current reads apply the effective-period filter.
8. **exam:manage remains the gate** — §18's Exam Specialist is still a future role.
