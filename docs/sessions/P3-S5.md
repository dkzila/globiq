## What Was Delivered

### 1. The unit-side mirror (`src/modules/exam-mapping/unit-coverage-service.ts` — new file in the §28 registry's exam-mapping module)

`getUnitExamCoverage(unitRef, query)` — the mirror of `getPublicExamCoverage` filtered by unit. Which exams need THIS canonical unit today:

- **Reader-scoped (§14/§15)**: resolves the country/language context itself (same pattern as the module's other public reads); only the reader's country's **ACTIVE** exams contribute — a GB exam's requirement on a GLOBAL unit never leaks into an IN read (and COMING_SOON markets reject the read entirely).
- **Current versions only (§36)**: the mirror answers "today" — the §36 window containing now; the historical mapping (seed's superseded UPSC window) stays on the coverage read's explicit `?version=` path and never appears here.
- **§8 effective period**: mappings in effect now (day-granular inclusive; future-dated requirements excluded — the Chandrayaan `2023-08-23` anchor passes).
- **One row per (exam × node)** with the full §8 vocabulary (depth, priority, relevance, likelihood, expected scope, effective period) + the exam's current version label + the covering node's §35 topic label + the §16 exam-page path (`…/exams/{slug}/` in the resolved locale).
- **§37 determinism**: exam name → exam slug → node priority → node name → mapping id. `examCount` (distinct exams) and `requirementCount` ship alongside `requirements`.
- Non-VERIFIED units resolve to the clean empty state (public reality — no mappings to mirror); unknown units are a typed `UNIT_NOT_FOUND` 404.
- Contract surfaces: `UnitExamRequirement`/`UnitExamCoverage` in `types.ts`; `unitCoverageQuerySchema` (country/language only — no `version` parameter by design) in `validation.ts`; both exported from the module `index.ts`.

## Key Decisions

1. **The mirror lives in the exam-mapping module** (per the §28 registry, P3-S3…S5) as a sibling service importing the module's shared internals — the same pattern as the P3-S4 engine. No new module, no new endpoint, no schema change.
2. **Current versions only, by design** — the panel answers "which exams need this TODAY"; history stays on the coverage read's explicit `?version=` path (§36). The query schema has no `version` parameter on purpose.
3. **`available: false` is now an honest empty state, not a placeholder** — the layer renders real rows whenever they exist and a quiet note otherwise; nothing is ever fabricated (the §22 rule from day one).
4. **Reader-country scoping over unit-scope scoping**: the mirror returns the reader's country's ACTIVE exams only — a GLOBAL unit's cross-country requirements are visible only inside each owning market (§14), never aggregated.
5. **The exam page consumes only existing endpoints** — the P3-S1 detail (versions + §16 path) and the P3-S3 coverage read are already the complete data layer; P3-S5 is a rendering session, which is why there are no new routes (§16 real routes are P4-S3's scope).
6. **No queue duplication**: the exam page points to the §11 engine section (single-exam mode) instead of re-implementing the queue — one engine, one ranking, one merge point (P5/P7 fold in there).
7. **Determinism documented in-Comparator**: the §37 ordering (exam name → slug → node priority → node name → mapping id) is explainable to a reader scanning the panel top-to-bottom and identical across calls (asserted).
